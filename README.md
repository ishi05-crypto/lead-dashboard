# 案件メール ダッシュボード

送客・入電通知メール（A-1〜C-1）を取り込み、**顧客氏名／電話番号／エリア／作業種別／規模・本数／希望日時／送客元／連絡期限** の8項目と、**メール受信日時・受信からの経過時間**を一覧できるダッシュボードにまとめます。
Python 3.10 以上の標準ライブラリだけで動きます（追加インストール不要）。

## 使い方

```bash
python3 manage.py import 'samples/*.eml'     # .eml を取り込む（重複は Message-ID で自動スキップ）
python3 manage.py serve --port 8000          # http://127.0.0.1:8000/ を開く
```

### 本番公開（実メールの自動取り込み）

**GitHub + Vercel + Neon(PostgreSQL) + CloudMailin** で公開します。受信箱から CloudMailin のアドレスへ自動転送するだけなので、Gmail・Outlook・レンタルサーバーなど、どのメールアドレスでも使えます。
手順は **[docs/SETUP.md](docs/SETUP.md)** を参照してください。

| 取り込み口 | 説明 |
|---|---|
| `POST /api/ingest?token=…` | 生メール / CloudMailin（Raw・JSON）/ Postmark / SendGrid（raw）の形式を受け付けます |
| `python3 manage.py import *.eml` | .eml ファイルを直接取り込みます（ローカル用） |
| `python3 manage.py imap --watch 120` | IMAP で定期取得します（ローカル常駐用。Vercel では使いません） |

環境変数: `DATABASE_URL`（無ければ SQLite）、`INGEST_TOKEN`、`DASHBOARD_USER` / `DASHBOARD_PASSWORD`

### 構成

```
api/ingest.py, api/leads.py   Vercel Functions（本体は mail_dashboard/server.py）
public/index.html             ダッシュボード画面
mail_dashboard/               解析・保存・HTTP 処理（ローカル・Vercel 共通）
```

## 送客元の判別とパース

判別の順序: ① 送信元ドメイン → ② 本文の特徴（転送メール対策） → ③ 本文中のドメイン。
本文は NFKC で正規化するため、全角／半角コロンや括弧の違いは吸収されます。

| コード | 形式 | 主な処理 |
|---|---|---|
| A-1 シェアテクノロジー | `■項目：値` | 問合せ元サイト名の `【…ヒア…】` を除去してフラグに移動。`【状況】` などの複数行の値も拾う |
| A-2 Ace | `■` と `【】` の2層形式 | 冒頭の「※…受注ベース…」から契約区分を判定。第1・第2候補の日時を併記 |
| A-3 はやぶさLP | `項目: 値` | 既知の項目名だけを拾う。成約率などの表は対象外 |
| B-1 wonder事務局 | 入電通知 | サイトURLのサブドメインからエリアを補完 |
| B-2/B-3 コールデータバンク | 入電通知 | アカウント名＋キャンペーン名で判別（キーワードは `config.py`）。判別できないものは B-X とし、短時間通話にはフラグを付ける |
| C-1 リショップナビ | 項目名の完全一致 | 宛名からブランド（例: はなまる造園）を、URL から案件IDを取り出す。氏名と電話番号は管理画面で確認 |

- **連絡期限** = 希望日時の **7日前**（第1候補を使用。時刻の指定があれば同じ時刻、日付だけならその日の 23:59）。希望日時が読み取れない案件は、本文に送客元が指定した期限があればそれを使い、無ければ「期限なし」と表示します。A-1 の本文にある「お客様への連絡期限」は、備考欄に残します。日数は `config.py` の `CONTACT_LEAD_DAYS` で変更できます。
- **受信日時・経過時間**: 一覧の左端に「◯時間◯分 経過」を大きく表示し、1分ごとに更新します。未対応のまま `ELAPSED_ALERT_HOURS`（既定 24時間）を超えた案件は赤字で警告し、上部の「未対応の最長経過」タイルにも反映します。
- 生メールは DB（`leads.db`）に保存されます。パーサーを直したあとに `python3 manage.py reparse` を実行すると、全件を再解析します（ステータスとメモはそのまま残ります）。
- テストの実行: `python3 -m unittest discover -s tests -t .`
